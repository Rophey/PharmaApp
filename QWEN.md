## Ключевые архитектурные решения

### MBRParameter — собственные значения для каждого MBR
Каждый MBR хранит **свои** значения параметров (value, tolerance, critical_deviation) в таблице `MBRParameter`. НЕ используется общая таблица `Parameter` для значений.

### API endpoints
- `POST /api/mbr/<id>/approve/` — утверждение MBR (JSON)
- `GET /api/mbr/<id>/` — получение данных MBR (JSON)
- `POST /mbr/<id>/new-version/` — создание новой версии
- `POST /mbr/<id>/delete/` — удаление черновика
- `POST /ebr/api/create/<id>/` — запуск партии (JSON)

### Валидация при утверждении MBR
Нельзя утвердить MBR если не заполнено:
- Продукт
- Технологические операции
- Параметры (значения > 0)
- Сырьё

### Фильтрация для технолога
На панели технолога показываются только **последние утверждённые версии** каждого продукта (по max document_id).
