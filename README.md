## Описание

PharmaApp — веб-приложение для управления полным жизненным циклом производства таблеток: от создания мастер-рецептур (MBR) до выпуска готовой партии (EBR), контроля качества и формирования отчётов. Система включает 7 ролей пользователей, симулятор оборудования, журнал аудита с электронной подписью и генерацию отчётов в Excel/CSV.

## Запуск проекта

### 1. Подготовка БД (PostgreSQL)

```bash
# Создание БД
createdb pharma_db
# или через psql:
psql -U postgres -c "CREATE DATABASE pharma_db;"
psql -U postgres -c "ALTER USER postgres PASSWORD 'pharma';"
```

### 2. Установка зависимостей

```bash
cd PharmaApp/pharma_project
pip install -r requirements.txt
```

### 3. Пересоздание БД и начальные данные

```bash
python recreate_db.py
python manage.py seed_data
```

### 4. Запуск сервера

```bash
python manage.py runserver
```

Открыть: http://127.0.0.1:8000/

## Жизненный цикл партии

```
1. Главный технолог: создание MBR → Утверждение
2. Технолог: запуск партии из утверждённого MBR → EBR «В ожидании»
3. Оператор: выбор партии → EBR «В работе» → «Выбор сырья» подтверждён
4. Оператор: ввод времени прессования → запуск симулятора → «Пресс запущен»
5. Симулятор: генерация 4 параметров (оборудование), обновление actual/max, проверка отклонений
6. Пресс завершён → «Экспертиза в ОКК» + уведомление
7. Сотрудник ОКК: ввод времени распадаемости → сохранение в EBR
8. Начальник ОКК: просмотр 10 параметров → подписание ЭП → EBR «Завершена»
```

### Статусы EBR

| Статус | Описание |
|--------|----------|
| **В ожидании** | Технолог запустил, оператор ещё не взял (operator IS NULL) |
| **В работе** | Оператор начал производство |
| **Завершена** | Подписана начальником ОКК |
| **Заблокирована** | Критическое отклонение, требует решения начальника ОКК |

### 5 параметров партии

| Параметр | Источник |
|----------|----------|
| Усилие прессования (кН) | 🤖 Оборудование (симулятор) |
| Толщина таблетки (мм) | 🤖 Оборудование (симулятор) |
| Масса таблетки (мг) | 🤖 Оборудование (симулятор) |
| Твёрдость таблетки (кПа) | 🤖 Оборудование (симулятор) |
| Время распадаемости (мин) | ✋ Ручной ввод (сотрудник ОКК), >0 и ≤4320 |

## Модули системы

### Управление пользователями (Системный администратор)
- Создание пользователей с валидацией полей (логин, пароль, ФИО)
- Деактивация / активация / удаление учётных записей
- Справочники: Сырьё (CRUD), Продукты (CRUD)
- Аудит всех действий

### Управление MBR (Главный технолог)
- Создание/редактирование черновиков MBR
- Утверждение MBR (валидация: продукт, операции, параметры, сырьё)
- Создание новых версий на основе утверждённых MBR
- Таблица всех MBR с фильтрацией

### Запуск и мониторинг партий (Технолог)
- Список утверждённых MBR с поиском по коду продукта
- Запуск партии → создание EBR с копированием данных из MBR
- Мониторинг партий в реальном времени (AJAX, каждые 3 сек)
- Обратный отсчёт пресса

### Производство (Оператор)
- Список ожидающих партий (operator IS NULL), AJAX-обновление
- «Мои партии» — активные задачи оператора, сортировка по времени
- Подтверждение операций («Выбор сырья», «Работа пресса»)
- Ввод времени прессования → запуск симулятора
- Обратный отсчёт пресса (обновление каждую секунду)
- Уведомление об отправке в ОКК

### Контроль качества (Сотрудник ОКК)
- Список заданий контроля качества (AJAX, каждые 3 сек)
- Модальное окно: визуальный контроль + время распадаемости + комментарий
- Валидация времени распадаемости: >0 и ≤4320 мин

### Подписание EBR (Начальник ОКК)
- **Проверка EBR:** партии «Завершена» (после ОКК, без подписи) и «Заблокирована»
- Просмотр всех 10 параметров, блок заключения ОКК, блок ЭП
- Кнопки: «Просмотр EBR», «Подтвердить ЭП», «Отклонить»
- **Архив:** подписанные партии с AJAX-обновлением (каждые 5 сек)
- **Аудит:** ссылка на полноценную страницу журнала аудита

### Панель директора
- **KPI-карточки:** выпуск (подписанные партии), % брака, отклонения, эффективность
- **Фильтр по датам** (ДД.ММ.ГГГГ) с AJAX-обновлением
- **Графики Chart.js:**
  - Круговая (pie): выпуск по продуктам
  - Гистограмма (bar): партии по статусам
- **Отчёты Excel/CSV:**
  - По выпуску: сводка по продуктам + детализация по партиям
  - По отклонениям: полная таблица с параметрами, типами, ответственными
  - Excel: форматированный (заголовок, синий фон `#2a83bd`, жирный шрифт)
  - CSV: `utf-8-sig` (BOM для корректной кириллицы)
- **Таблица «Последние отчёты»:** последние 6 записей
- **Синхронизация Deviation** при каждой загрузке: анализ EBRActualParameter → создание Deviation

### Журнал аудита
- Фильтры по пользователю, действию, дате
- Поиск по документу
- Пагинация (25 записей)
- Экспорт в CSV
- Столбец «Документ» с номером партии/кодом MBR и ссылками

## Архитектурные решения

### MBRParameter — собственные значения для каждого MBR
Каждый MBR хранит свои значения параметров (`value`, `tolerance`, `critical_deviation`) в таблице `MBRParameter`. Не используется общая таблица `Parameter` для значений.

### EBR: две модели параметров
- **EBRNominalParameter** — «как должно быть» (5 записей, копируются из MBR)
  - `nominal_value` — номинал из MBRParameter.value
  - `tolerance_value` — абсолютный допуск = nominal × (tolerance% / 100)
  - `critical_value` — абсолютное критическое = nominal × (critical% / 100)
- **EBRActualParameter** — «как на самом деле» (5 записей, заполняются в процессе)
  - `actual_value` — последнее введённое значение
  - `max_value` — максимум за всё время (NULL при критическом отклонении)
  - `source` — `'equipment'` (авто) или `'manual'` (ручной)

### Сравнение отклонений
Идёт через `diff = abs(actual_value - nominal_value)` с абсолютными `tolerance_value` / `critical_value`, а не с процентами.

### Симулятор оборудования
Генерирует значения относительно номинальных параметров партии:
- 88% — норма (±50% от допуска)
- 10% — предупреждение (50–90% от допуска)
- 2% — отклонение (90–100% от допуска)
- 0.5% — критическое (>100%)

Поддерживает несколько параллельных партий (thread-safe словарь `active_productions`).

### Номер партии
Формат: `B-<Код продукта>-<Год>-<Номер>` (например: `B-ASP-500-2026-001`)
